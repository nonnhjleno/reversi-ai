# 提出ZIPの形式と保存先

## アップロード形式

2026-11-10の利用者指示により、ZIPには`reversi.py`と、その実行に必要な付随ファイルだけを入れる。`web.py`とGUI用のHTML・CSS・JavaScriptなどは含めない。現在の提出物はZIP直下にファイルを置き、外側の`reversi_player/`ディレクトリを入れない。

現在のPhase 5版に必要なファイルは次の5つ。設定も実行資産なので省かない。

| ZIP内のファイル | 役割 |
|---|---|
| reversi.py | 起動ファイル・コマンド処理・盤面の確定更新 |
| ai_engine.py | 評価・固定深度探索などのAI処理 |
| search_trace.py | reversi.pyからimportする計測・設定接続処理 |
| timed_search.py | 時間制御付きの探索・着手選択 |
| response_config.json | 7秒目標・開始/停止余裕・最大深度4の設定 |

`harness/`、テスト、docs、manifest、venv、cache、過去の評価ログをZIPへ入れない。manifestはZIPの外へ保存する。将来モデルが必要になった場合は、その実行に必要なモデル資産を明示して追加し、別名のZIPとmanifestで検証する。今回のZIPに学習モデルはない。

## 最新の提出候補（Python 3.7以降の互換性修正）

再アップロードには[Python 3.7対応ZIP](../submissions/phase5/ranger-phase5-7s-py37-20261113.zip)を使う。[manifest](../submissions/phase5/ranger-phase5-7s-py37-20261113.manifest.json)はZIPの外に保存する。以下の初回修正版と旧ZIPは履歴として残す。

利用者から、初回修正版でも表示名が`nan`となり、棋譜は着手前に`invalid move`となるとの報告があった。結果は定時更新であり、表示が最新ZIPの実行結果かは未確認である。初回修正版をPython 3.7.9・3.8.10・3.9.13で起動すると、`typing.TypeAlias`のimportで失敗し、`name`の応答前に終了することを再現した。

`TypeAlias`のimportを型検査時だけに限定し、実行時に評価される型エイリアスと`cast`の型指定を旧Pythonでも利用できる表記へ変更した。名前は`ranger`、探索・評価・盤面処理・7秒設定は維持した。

新ZIPはWindowsのPython 3.7.9・3.8.10・3.9.13・3.10.11・3.11.9・3.13.5で、全7コマンドと各2局、計12局の先後交換対局に成功した。合法手・盤面・終局結果を独立したルール実装と照合し、終了コード0・stderrなしを確認した。これは互換性と対局動作の確認であり、棋力向上を示すものではない。詳細は[再修正の検証記録](reports/20261113_server_python37_compatibility.md)を参照する。

ZIPのSHA-256は`55d1bb68cd2ecc8bd140314cc7fde96e3a9a4e2b74453cab4202981a96486671`、サイズは18535 bytes。サーバーのPythonと起動ログは未取得であり、サーバー実機の原因と復旧は未確認である。再アップロード後に、名前と実際の着手が正常に取得されるかを確認する。

## 2026-11-13のPython互換性修正（初回・履歴）

`ranger-phase5-7s-20261110.zip`のアップロード後に表示名が`nan`となり、対戦できないと利用者から報告があった。旧ZIPをWindowsのPython 3.10.11・3.11.9で起動すると、Python 3.12以降にしか対応しない`type`文で`SyntaxError`となり、`name`に応答しなかった。サーバーのPythonとログは未確認なので、実機の原因は断定しない。

`ai_engine.py`と`timed_search.py`の型定義を`TypeAlias`付きの代入へ変更し、[修正版ZIP](../submissions/phase5/ranger-phase5-7s-py310-20261113.zip)と[manifest](../submissions/phase5/ranger-phase5-7s-py310-20261113.manifest.json)を別名で作成した。再アップロードにはこの修正版ZIPを選ぶ。旧ZIP・固定相手・探索処理・評価関数・7秒設定は変更していない。

修正版はWindowsのPython 3.10.11・3.11.9・3.13.5で、展開物の全7コマンドと、固定random_v0との各2局、計6局の先後交換対局に成功した。これは互換性と対局動作の確認であり、棋力向上やサーバー実機での復旧を示すものではない。ZIPのSHA-256は`7349b9c3b5b779460536815ebd001dfa0f0e026de798e57135b71c630bf0ff74`、サイズは18502 bytes。

## 今回の確認結果

ZIPの全memberとCRCを確認し、重複・ディレクトリ・余分なファイルがなく、5ファイルの実bytesが現行ソースおよび既存の検証済みPhase 5 ZIPと一致した。

新規領域へ展開し、projectのPYTHONPATHと評価用環境変数を渡さず、空のcwdから直接CPython 3.13.5 / Windowsで起動した。`name`・`ask`・`play`・`showboard`・`result`・`genmove`・`quit`の7種類、合法手・盤面の独立referee一致、終了コード0・stderrなしを確認した。8コマンド全体の外部経過は0.528461秒で、コマンド別の期限や未知サーバーでの7秒以内応答を検証した値ではない。1局の対戦評価や棋力向上の証拠として扱わない。

AIコード・設定を変更しておらず、保存済みFull11工程・pytest1611件・strict19本に対応する48source hashが今回も一致した。今回はZIP構成と展開起動を確認し、Fullは再実行していない。新しい本番moduleや実行契約を追加していないため、runtimeの図・契約・品質scopeも変更していない。検証原記録は`evaluation_results/submission_packages/run-85462495dbff418081b30c3a5d5aef24/`へ新規保存した。

## アップロード前の確認

1. 上記ZIPを選び、manifestとZIPのSHA-256を照合する。manifestやフォルダ全体を一緒にZIPへ詰め直さない。
2. サーバーのPython・起動名・起動方法が`reversi.py`と付随ファイルに対応するかを確認する。ZIP形式は利用者の指定で確認できたが、サーバー実機での実行は未確認である。
3. 新uploadで旧ファイルが消えるため、提出ZIPと戻すZIPを別媒体へ保管する。外部バックアップの実施と、その後のuploadは今回行っていない。
4. 実機では先後・相手を変えた複数局、エラーと取得可能な時間情報を記録する。試行・復旧の手順は[Phase 5のサーバー試行記録](reports/20261108_phase5_server_trials.md)を参照する。そこにあるZIP形式の未確認記載は2026-11-08時点の履歴であり、形式の現行情報は本書とする。
