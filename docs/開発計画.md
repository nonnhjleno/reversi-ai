# リバーシ対戦プログラムの開発計画

## 目標と前提

最終目標は、自己対戦で改善する強化学習モデルを `reversi_player/reversi.py` の着手選択へ組み込み、授業仕様の制限時間内に強い手を返すこと。強さは印象ではなく、固定した相手との対局で確認する。コマンドやルールの正本は `プログラム開発方法.md` とし、ここには工程と完了条件だけを記す。

`reversi_player/reversi.py` には盤面操作、ランダム着手、`result` コマンドがある。全体の対局完走と処理時間は引き続き確認する。`102400-games/data.py` は棋譜の形式を説明しているが、棋譜の品質や利用方法は未検証である。`先生からのメモ/20260925.md` の「まず動かす→賢くする→最後に高速化する」という順序を採用する。`先生からのメモ/20261002.md` はモデルを少しずつ賢くするという記録で、具体的な実装方法は示していない。

## 1. 対戦プログラムを正しく完成させる

既存の `Board` とコマンド処理を土台に、合法手判定、着手後の反転、パス、終局、`result`、不正入力時の扱いを整理する。盤面の処理と標準入出力の責任を分け、学習や探索から盤面の処理を再利用できるようにする。まずランダム着手で終局まで対局できる状態にする。

完了条件: 初期盤面、合法手、反転、パス、終局と勝敗を小さな局面で確認できる。全コマンドの出力が仕様に合い、GUIから1局を終えられる。通常コマンドと `genmove` がそれぞれの時間制限を守る。標準出力にデバッグ文が混ざらない。

## 2. 強さを測る基準を作る

ランダム着手版を保存して比較対象にする。合法手を列挙して自己対戦できる仕組みを作り、乱数シード、先後、結果、実行時間を記録する。次に、評価関数と探索を用いる対戦相手を作る。これを強化学習モデルの比較対象にし、終盤の読み切りも検討する。探索の深さや高速化は計測結果に基づいて決める。

完了条件: 同じ条件の対戦を再実行でき、ランダム版・探索版それぞれの勝敗と時間を比較できる。先手と後手を入れ替えて評価できる。

## 3. 学習データと実行環境を確かめる

Pythonのバージョン、CPU/GPU、学習に使える時間と保存容量を確認する。配布された `102400-games` の棋譜は、出所を確かめたうえで形式、パス、合法性、結果を検査する。既存棋譜を使う場合、それによる初期学習と、その後の自己対戦による強化学習を区別する。学習用データは対局単位で分割し、評価用の対局が学習へ混入しないようにする。

完了条件: 棋譜を再生して不正な局を検出できる。環境に応じた学習方式と計算予算を決められる。

## 4. 自己対戦で学習する

具体的な方式・論文・評価条件は [強化方針.md](強化方針.md) に置く。現時点の第一推奨案は、軽量なn-tuple価値モデルを自己対戦TD学習で改善し、学習後に探索と組み合わせる方式である。方策・価値モデルと学習中の探索を組み合わせる方式は、計算資源と軽量方式の限界を確認した後の拡張候補とする。自己対戦の局面・選択方針・最終結果を記録し、学習した候補を旧版および固定対戦相手と対局させ、改善が確認できた版だけを採用する。盤面の対称性を利用する場合は、座標と着手の変換が一致することを確認する。

完了条件: 「自己対戦→学習→評価→採用または保留」を繰り返せる。モデル、設定、乱数シード、対戦成績を再現可能な形で保存できる。学習しただけで強くなったとは判断せず、固定相手との対戦で改善を確認する。

## 5. 対戦プログラムへ組み込み、実測する

採用したモデルを `genmove` から使い、合法手のみを選ぶ。モデルが読み込めない場合や時間切れが近い場合の動作を決める。`web.py` は要求ごとに対戦プログラムを起動するため、モデル読み込みを含む起動直後の時間も測る。終盤の読み切りを加える場合は、残り手数だけで決め打ちせず実測した時間内で探索する。

完了条件: GUIとコマンドの両方で最後まで対局できる。固定したランダム版・探索版との複数局で、先後を入れ替えた結果と実行時間を記録し、採用版がどこまで強くなったかを説明できる。
