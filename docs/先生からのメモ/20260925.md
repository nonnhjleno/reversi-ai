##要点

- 開発は「ランダムでも動く状態にする → 賢くする → 最後に高速化する」の順で進める。残り手数が少ない場合は全パターンの列挙が有効で、高速化が役立つ場面もある。
- 標準出力と標準エラー出力を使い分ける。`print()`は時間がかかり、探索や描画に影響することがある。デバッグ出力は標準エラー出力に出し、最終版では出力を抑える。
- 読みやすさを重視し、命名規則、コメント、private/publicの区別などのルールを統一する。Python 3.11の機能や型チェックも活用する。
- AIの提案や変更内容を人間が理解してから進める。変更方法を具体的に説明させ、定期的に矛盾点も確認する。

##次にやること

- まず、ランダムな状況でも動作する状態を目指す。
- 標準出力と標準エラー出力の用途を整理し、デバッグ出力は標準エラー出力に出す。
- 命名規則、privateメンバーの扱い、コメントの書き方など、コーディングルールを決める。
- Pythonのバージョンと型チェックの方針を決め、コードに反映する。
- AIに変更を依頼するときは、具体的な変更方法と意図の説明を求め、内容を確認してから進める。

##確認したいこと

- 「ランダムでも動く」とは、どの入力や状況で動作できればよいか。
- 標準入出力や`web.py`への出力は、どの実行環境・仕様を前提にしているか。
- Python 3.11の使用と型チェックは、プロジェクトで確定しているか。
- テスト計画やデバッグ出力の整理を、いつ・誰が行うか。
- AIに変更を任せる範囲と、人間が確認してから進める手順をどう決めるか。
