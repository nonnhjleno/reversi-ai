# AIモデル運用方針

更新日: 2026-10-02

このプロジェクトでは、ChatGPT Plusの利用枠を節約しながら、作業の難しさに応じてモデルを使い分ける。

## 基本方針

| 用途 | モデルと設定 | 主な作業 |
| --- | --- | --- |
| 日常作業 | GPT-6 Luna / High / Standard | 小さな実装、入力検証、単体テスト、コメント・文書整理、単純な修正 |
| 設計・難しい実装 | GPT-6.1 Sol / Medium / Standard | コンポーネント分割、評価関数、探索処理、複数ファイルにまたがる変更 |
| 難所・最終確認 | GPT-6 Astra / Light / Standard | 全体設計レビュー、解決困難なバグ、終局・パス処理、提出前の仕様適合確認 |

通常はLunaから始める。設計判断や複数機能の連携が必要ならGPT-6.1 Solへ切り替え、Astraは重要な判断や最終レビューに限定する。

## GPT-6.1 Solの位置づけ

- GPT-6 Solを更新したモデル。複雑なコーディング、コンピューター操作、専門的な作業で、GPT-6 Astraに近い性能をより低いコストで提供する位置づけ。
- OpenAIのAPI評価では、複雑なソフトウェア開発課題でAstraと同程度の結果をより低いタスク費用で達成したと報告されている。評価結果は特定の課題・設定に基づくもので、すべての作業でAstraと同等という意味ではない。
- ChatGPT WorkとCodexで提供される。Plusを含む対象プランに順次展開されているが、アカウントやワークスペースの設定によって、モデル選択欄にまだ表示されない場合がある。通常のChatでの提供とは別扱い。
- APIのモデルIDは `gpt-6.1-sol`。API仕様ではコンテキスト長105万トークン、最大出力12万8千トークン、知識カットオフは2026-04-30。実際の上限はChatGPT WorkやCodexでは異なる場合がある。
- APIで選べる推論レベルは low、medium（既定）、high、xhigh、max。WorkやCodexの選択肢は製品やアカウントによって異なる。まずMediumを使い、難しい課題で必要に応じて上げる。高い推論レベルは利用枠を多く使うことがあり、常に回答が改善するとは限らない。
- API標準料金は入力100万トークンあたり2ドル、出力100万トークンあたり10ドルで、GPT-6 Astraの標準料金の約5分の1。これはAPI料金の比較であり、ChatGPT Plus／Codexの利用枠や消費量にそのまま当てはめない。

## 開発段階ごとの使い分け

1. ファイル構成と責務の設計はGPT-6.1 Solを使う。
2. ランダム着手版、`result`、入力処理、基本テストはLunaを使う。
3. 評価関数、Minimax、αβ枝刈り、終盤の完全読みはGPT-6.1 Solを使う。
4. Solでも解決できない不具合や、各段階の最終レビューだけAstraを使う。

## モデルを切り替える基準

- Lunaの回答で要件漏れや修正のやり直しが続く場合はGPT-6.1 Solへ切り替える。
- 変更が複数コンポーネントに及ぶ場合は、最初からGPT-6.1 Solを使う。
- Astraは常用せず、設計監査や原因の分からない重大な不具合に使う。
- Fast、Max、Ultraは原則として使わない。必要性を説明できる場合だけ一時的に使う。
- Solの推論レベルを上げる前に、指示の明確さ、必要なファイル、実行権限が揃っているか確認する。

## 利用枠を節約する方法

- 対象ファイル、完了条件、実行するテストを一度の依頼にまとめる。
- 関係のないファイルや長い資料をコンテキストへ入れない。
- 大きな作業は段階に分けるが、細かすぎる確認の往復は避ける。
- 長くなった会話をそのまま使い続けず、開発段階が変わったら新しいスレッドを検討する。
- `/status` または利用状況画面で残りの利用枠を定期的に確認する。
- クラウド実行より、必要なファイルだけを扱うローカル実行を優先する。
