# Phase 7の自己対戦TD(0)設計

Phase 6.5を統合したmainの `81b7b34` から、Phase 6の全ゼロモデルとPhase 6.5の凍結モデルを比較する。両初期資産はファイルのSHA-256とmodel IDを照合する。学習は `tools/` に置く。対戦はPhase 6の推論と既存の独立ハーネスを使う。[段階設計](リバーシAI段階開発・評価設計書.md#phase-7自己対戦td0学習と学習効果の検証)・[モデル仕様](phase6_design.md)・[事前学習報告](reports/20261118_phase65_supervised.md)

## 状態とオンライン更新

状態は盤面と次の手番の組。合法な着手の後と強制パスの後は相手の手番になる。パスは片方だけに合法手がない場合の遷移で、盤面は同じ。双方に合法手がない盤面で終局とする。初期化は各局とも通常の初期盤面・黒番。対局中の1遷移を1回更新し、最後の着手が生んだ終局も更新対象とする。

Phase 6と共通の2-tuple・3-tuple、8対称性、手番別LUT、1,872重みと448参照を使う。同じ重みが参照された回数を `cᵢ(s)` とし、黒視点の価値を `Vθ(s) = tanh(Σᵢ cᵢ(s)θᵢ)` とする。学習時も参照回数分のbinary64加算を用いる。

割引率は1、途中報酬は0。非終局の次状態では `u = Vθ(s′)`、終局に入るときは `u = z` とする。`z` は黒勝ち+1、白勝ち−1、引き分け0。更新前の同じ重みで `u` と `Vθ(s)` を求め、`δ = u − Vθ(s)` と `θᵢ ← θᵢ + αδ(1−V(s)²)cᵢ(s)` を適用する。更新に使うのは現在状態の特徴だけ。目標側の微分・参照回数の正規化・白番の符号反転は行わない。終局後の更新も行わない。

## 方策と記録

両色は同じモデルを使う。着手可能なら専用の `random.Random(seed)` で探索するかを決め、探索時は行・列順の合法手から一様に選ぶ。εが0なら乱数を使わない。パスや終局でも乱数を使わない。乱数状態を局間で継ぐ。greedyは着手後の次手番の価値を黒が最大化、白が最小化し、同点なら行・列順の先頭を選ぶ。選択スコアはPhase 6と同じで、終局勝敗が±2の外側、石差は同じ勝敗の優先順位、引き分けは0。TD目標にはこのスコアを使わない。

棋譜と対局集計をJSON Lines、checkpointの推論資産を既存のモデルJSON、再開情報をJSONに保存する。再開は確定局境界に限る。既存のモデルIDと実bytesのhash、累積局数・更新・着手・パス、乱数、初期モデル、学習率・ε・γ・seed、コード・環境、設定、直前のcheckpointの識別、棋譜のhash、保存時刻を記録する。最後に保存したメタデータを完成の印とし、欠落・破損・不一致は明示して停止する。時計を除く棋譜、モデルID、重み、乱数、累積件数を連続実行と別プロセス再開で照合する。

| 項目 | 条件 |
|---|---|
| 初期化 | Phase 6全ゼロとPhase 6.5凍結モデル |
| 学習seed | 701、702、703。両系列で共通 |
| 小規模選定 | seed 701で各初期化80局。学習率0.0000625／0.00025、ε 0.10／0.20の4組。どちらも固定値 |
| 選定順序 | developmentの選定用4ペアで、固定positional_v1に対する両系列の平均勝ち点率を最大化。同点は低い学習率、次に小さいε |

| 昇格条件 | 数学、合法性、再現性、保存、有限値が合格し、`abs(V) >= 0.99` が連続した主要区間で5%未満。1,000局の計測から10,000局までの追加費用が妥当な場合に進む |
| 最大規模 | 50,000局は主要系列の10,000局結果で改善の兆候と実行費用を確認した場合に限る |
| 比較用序盤 | Phase 0 developmentの固定12先後交換ペア、評価seed 20261119。選定用4ペアを重ねない。Phase 0 held-outを開かない |
| 比較 | 各時点で固定positional_v1、明示 `eval-depth2.json` の固定search_v1、同学習量の系列間直接対局 |
| 外部上限 | startup 5秒、通常1秒、genmove 10秒。Phase 6側は予算unknown、対局は参考評価 |
| 区間と候補 | 先後交換ペアの再標本化と学習seedの分散を別に報告する。Phase 8候補は各系列のseed 701を代表とし、全seedの学習前後の勝ち点を把握したうえで時点を判断する |

選定用と比較用の序盤はdevelopmentの対称同値な着手列をまとめ、別のD4群とする。自己対戦には外部棋譜・固定序盤を与えない。事前学習済みの由来はPhase 6.5の固定資産である。自己対戦と比較対局の8着手prefixおよび完全着手列についてD4同値を監査する。同じ序盤の偶発的な通過は件数と範囲を記録する。評価は凍結モデルをPhase 6の1手選択に渡し、棋譜・通信・石差・異常・応答時間を保存する。

評価対象は学習前後の同一条件の差、系列間の初期差、同学習量の差、実時間の差。学習seedをまとめた場合も各seedの結果を残す。学習ログには報酬分布、対局長、パス、TD誤差・価値・更新量の分布、飽和、黒白別の重みを記録する。Phase 8では凍結候補の葉評価を同じ重みの1手選択と比較する。

## 再現と検証

学習の入口は `python -B -m tools.phase7_train INITIAL_JSON OUTPUT_DIR --until N --seed SEED --rate RATE --epsilon EPSILON`。初期JSONは絶対パスで指定する。継続は `--resume PREVIOUS_DIR` を加え、同一条件で累積局数を増やす。失敗した区間の保存先は原証拠として残す。途中で確定局数を記録する場合も、同じ設定で再開する。

`python -B -m tools.phase7_eval prepare OPENING_DIR` で選定用と比較用の固定序盤を保存し、`python -B -m tools.phase7_eval match MODEL_JSON OPPONENT OPENINGS_JSON OUTPUT_DIR` で対局する。相手にはPhase 6形式のモデルのパス、`positional_v1`、または `search_v1` を指定する。各モデルが別プロセスで読み込まれ、選択中に重みは変わらない。学習量ごとの対局と学習統計は `tools.phase7_results` で照合する。

独立検証は、参照特徴と有限差分、短い合法対局の各手、Phase 6方策との照合、別プロセスへの再開、checkpoint破損の拒否を対象とする。通常のFullには小規模テストだけを加える。参考対局と長時間学習は別の実行領域に保存する。
