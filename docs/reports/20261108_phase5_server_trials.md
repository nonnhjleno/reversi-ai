## 0.1秒ずつ増やす場合

7.0秒版で試した対局条件を記録してから、必要があると判断した場合だけ7.1秒、7.2秒の別候補を作る。今の最大深度は4で、代表局面では早期完了したため、予算の増量だけで着手が強くなるとは限らない。最大深度や評価関数まで同時に変更せず、時間だけの比較と区別する。

調整するのは候補/提出側のresponse_config.jsonであり、baselines/search_v1の設定・engine・manifestを更新しない。new_depth_margin_ns=1000000000、stop_margin_ns=500000000を維持するなら7.1秒目標で開始限界6.1秒・停止要求6.6秒となるが、これは新しい未検証候補である。変更後は必要なローカル検証・ZIP展開確認を行い、新しいZIPとhashを作ってから利用者がアップロードする。このGoalで増量試験は行っていない。

少数局の成功は今後の全局面での安全保証ではない。相手・先後・局面と勝敗、異常、確認できた時間情報を分ける。予算を増やして異常が出たら、そのZIPを保持して記録し、直前に実機確認できたZIPを再アップロードして戻す。原因が不明なまま、失敗を相手や通信のせいと断定しない。
