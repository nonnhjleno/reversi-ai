# Ranger 深度5の実効予算と安定性

## 2026-11-14の540局で適用された予算

**540局のA0・A1は、どちらも順序付きAlpha-Betaの固定深度2で動作する起動条件だった。** 旧7系列の実行argv、両役の設定、全genmoveの外部期限、起動対象のhashを照合した。A0/A1の実験用JSONには目標7秒と深度4/5が書かれていたが、旧対局ではそのローカル設定を読む経路に入らなかった。

1. 旧CLIの全7系列で予算設定ファイルの指定が省略されていた。ハーネスは、設定省略時に `{"format_version":2,"budget":{"kind":"unknown"},"search":{}}` を両役の一時JSONへ書いた。保存済み540局の各プレイヤー記録にも同じ設定が残っている。
2. `Player` は親プロセスの評価環境変数を除き、生成した設定・trace・contextのパスを子に渡した。子のcwdは対象スクリプトの親ディレクトリだった。
3. `search_trace.load()` は `unknown` と空の `search` に対し `None` を返す。一方、`REVERSI_EVAL_CONFIG` は設定済みなので `reversi.main()` は `TimedSelector` を生成せず、`Board` の既定選択器が使われる。既定は固定深度2で、`search_iterative()` に渡る `limit_ns` は存在しない。
4. 当時の実験資産を使った新規の最小再現でも、子プロセス2本とも `trace_active=false`、`timed_selector_active=false`、`fixed_default_depth=2` を記録した。旧540局の子プロセス環境全体と一時設定ファイルの実バイトは残っていない。旧経路の判定には保存された正規化設定、CLI、ハーネスの起動規則、当時のAIソースを使った。手ごとの反復や探索時間の実測値もない。

旧genmoveの `limit_ns=10_000_000_000` は外部の受信期限だった。内部100msを指定した記録はない。直接対局の平均45.6/45.2msは、固定深度2の計算量と通信を含む応答時間であり、探索予算を示す値ではない。同一コードと同一深度で判定したことは、270対応組すべての棋譜と最終盤面が一致した結果と整合する。旧勝ち点はその固定深度条件の参考値として扱い、深度4対5の差の推定には使わない。

通常起動では評価設定の環境変数がなく、ローカルの7秒ポリシーが使われる。正式な時間設定を明示した起動では `search_trace.load()` が時間上限を受理し、その上限がある場合は反復開始・停止の期限をポリシーの期限との早い方に絞る。正式設定で受理する深度上限は4。旧540局の `unknown` は、こうした時間上限の指定とは別の分岐である。

## 新しい比較の条件

分岐元は `origin/main` の `d5cbbb31a87d0afc5be5a4287221eb7af87a6216`。旧実験コミット `db6eadf` からAI本体・ハーネスの差分はなく、旧実験と同じ従来評価のA0/A1実行資産をバイト単位で照合してコピーした。角接続辺石10%評価はこの比較に入っていない。

新規比較では、実験ドライバーの起動時だけ、ハーネスが評価用環境変数を子に渡さない構成にした。通常のRangerがローカル `response_config.json` を読み、A0は深度4、A1は深度5を上限とする。内部目標7秒、反復開始期限6秒、停止要求6.5秒、後処理予約0.5秒、外部genmove期限10秒。時間対応探索の追加上限 `limit_ns` は両側 `None` で、`ResponsePolicy` が停止期限を決める。

旧局面証拠からdevelopment由来13局面を測定前に固定した。内訳は通常着手11局面、パス・終局各1局面。前回の診断3局面と旧CPU競合での中断例を含む。それぞれ深度4/5、診断あり/素のコピーを通常負荷と同じ論理CPU上に競合プロセス1本を置く条件で各3回ずつ測った。診断のあり/なしの順序は局面・反復ごとに入れ替えた。深度・採用手の計測は実験用JSONLで保存し、素のコピーではプロトコル応答と外部時間を比較した。

この実験の診断は正式trace4の範囲外で、深度5の正式資格や提出サーバーの時間保証は得られない。局面には中断しやすい例を意図的に含めているため、完了率とnearest-rankのp95はこの標本内の参考値とする。

## 7秒経路の参考対局

通常負荷で、事前固定したdevelopment序盤5件をA0対A1で先後交換し、10局すべて完走した。A1は5勝1分4敗で5.5点（55%）、A0は4.5点。先後交換ペアごとのA1−A0の差は順に0、+1、−2、+2、0点。全ペアで棋譜が分岐し、最初の分岐は序盤再生後1〜6手目だった。

A1の通常着手264件はすべて深度5を開始し、208件（78.8%）で完了・採用した。残り56件は時間停止で深度4へ戻った。深度5を採用した208件のうち60件で、同じ探索の深度4完了手から着手が変わった。A0の通常着手256件はすべて深度4を完了・採用した。固定局面の試行と対局中の試行では局面構成が異なるため、完了率は別々に扱う。

外部genmove時間はパス・終局確認を含め、A0が275件で平均0.859秒、p95 2.585秒、最大3.396秒。A1は277件で平均2.663秒、p95 6.506秒、最大6.611秒。通常着手の内部探索はA1で平均2.789秒、中央値1.889秒、p95 6.500秒、最大6.588秒。6.5秒は探索中の停止要求期限であり、停止確認と応答まで遅れ得る。7/8/10秒超過は各0件。timeout、不正手、異常終了、診断と実応答の不一致も各0件。

同一相手の補足比較として、最初の登録済み序盤1件を固定 `search_v1` の通常起動に対して使い、同じseed・先後・外部期限で各候補2局を実行した。4局すべて完走し、A0・A1とも1勝1敗。対応する2局はどちらも棋譜が変わり、A1−A0の勝ち点差は黒で−1点、白で+1点だった。A1は54/54着手で深度5を開始、41/54（75.9%）で完了・採用し、そのうち15件で深度4の手から変わった。A1の外部応答最大は6.506秒。7/8/10秒超過、timeout、不正手、異常終了、診断不一致は0件。基準AIの内部深度イベントは取得していない。

## 採否と次の優先事項

**深度5の提出版への採用は保留。** 旧540局の棋力差は深度差の検証に使えない。今回の実対局では深度5が着手を変えたが、直接対局は5先後ペア、同一相手は1序盤に限られ、勝ち点の改善は確定できない。通常負荷の実戦でも候補着手の約2割で深度5が中断した。提出サーバーでの10秒適合は未確認。

次に優先するのは、正しい7秒起動を各着手の証拠で確認しながら、序盤と相手を増やした同条件の先後交換比較を事前登録して行うこと。ローカル実測と提出環境の応答差も確認する。完了不足が実用上の制約となる場合は、測定した中断局面を基準に探索効率の改善を別実験で評価する。

## 品質と証拠

Windowsの直接CPython 3.13.5で、深度5の独立オラクル照合・深度5中断時の深度4結果保持・正式traceの深度上限・パス・終局・GUI連携を含む既存の関連テスト16件が通過した。pytestの実終了コードは0。製品コードと正式契約に差分がないため、今回の実験ではFullを再実行していない。

原証拠はローカルの `evaluation_results/depth5-budget-stability-20261118/` に保存した。旧540局と今回の試行は別領域で管理する。
