# resultコマンドの追加手順と不具合の検討

> 履歴資料（2026-10-13整理）。本文の「現行」「未実装」、節番号・行番号、実行結果は記録当時のものです。今の作業指示には使わず、[操作手順](../../ハーネス.md)、[現行契約](../harness_contracts.md)、[現行構造](../harness_architecture.md)、[AI分離の設計案](../../リバーシAI分離設計.md)を優先してください。

状態: 実装・確認済み（2026-10-02）。対象は `reversi_player/reversi.py`。仕様の参照先は `プログラム開発方法.md` の「(f) result」「(2) リバーシのルール」「(3) 処理時間」。

## 追加する処理

盤面に対して「合法手の有無を調べる」「終局時の勝敗を返す」「応答を出力する」の順で処理する。問い合わせによって石を置いたり手番を進めたりしない。盤面が埋まっていなくても、両色とも合法手がなければ終局となる。片方だけに合法手がない状態はパスであり、対局中である。

### 1. Boardに _has_legal_move(self, color) を追加する

`_ask()` の近くに、指定色に合法手が1つでもあるかを返す内部メソッドを置く。引数は内部から渡す有効な色 `B` または `W`、戻り値は `bool` とする。

1. 行 `y`、列 `x` の順に全64マスを走査する。
2. `Pos(x, y)` を作り、`self._ask(color, pos)` を呼ぶ。
3. 合法手が見つかったら、その時点で `True` を返す。
4. 全マスに合法手がなければ、ループの外で `False` を返す。

`_ask()` が確認するのは1マスからの8方向なので、その外側で全マスを調べる必要がある。既存の `ask()` は応答を出力し、`_genmove()` は着手して盤面を変更するため、この判定からは呼ばない。

### 2. Boardに result(self) を追加する

公開メソッド `result()` は、引数なしで現在の盤面を読み、仕様の応答文字列を返す。ここでは標準出力への出力を行わない。

1. 黒に合法手があれば対局中の結果を返す。
2. 黒に合法手がなければ白を調べ、白に合法手があっても対局中の結果を返す。
3. 両色とも合法手がない場合だけ、各行の黒石数と白石数を合計する。空きマスは含めない。
4. 仕様に従って黒勝ち・白勝ち・同数の結果を返す。どの経路でも文字列を返し、`None` のまま終了する経路を作らない。

手番やパスの履歴は不要である。現在の盤面だけから毎回判定し、結果を保存する変数やキャッシュは設けない。

### 3. main()にコマンド分岐を追加する

`showboard` の分岐の後など、既存の分岐列に `cmd == ['result']` の分岐を追加する。`board.result()` の戻り値を、改行付きの1行として `flush=True` で出力する。`main()` の対応コマンドを説明するdocstringにも `result` を追加する。

これにより、問い合わせは `main() → Board.result() → _has_legal_move() → _ask() → _get_reverse_pos()` の順に進み、結果が戻ると `main()` が1回だけ応答を出す。

### 4. GUIとの通信で影響する既存箇所を整える

同時に行う関連修正として、`ask()` の着手不可時の出力、および `genmove()` の座標・着手不可の出力に `flush=True` を付ける。

`web.py` はパイプで1行の応答を待つ。特に `_make_response()` は盤面表示と全64マスの `ask` の後に `result` を呼ぶため、`ask` の応答がバッファに残れば、正しく追加した `result` まで処理が届かない。これは現行コードの問題であり、終局判定ロジックの不具合と混同しない。

## 起こりうる不具合と防ぎ方

| 不具合 | 起きる原因 | 防ぎ方・確認方法 |
| --- | --- | --- |
| パスを終局と誤認する | 片方の色だけを調べる、または「どちらかに手がない」ことを終局条件にする | 両色とも合法手がない場合だけ勝敗を返す。片方だけに合法手がある局面を両色分確認する |
| 空きマスが残る終局を認識しない | 盤面が満杯かだけで判定する | 全マスの合法性で終局を判定する。空きが残る終局も確認する |
| 対局中に勝ち負けを返す | 終局確認より先に石数を比較する | 合法手の有無を先に判定する。石数差が大きい対局中の局面も確認する |
| 合法手を見落とす | 最初の不合法マスで `False` を返す、座標の順序を逆にする、走査の範囲が不足する | `False` は全マス確認後に返す。`Pos(x, y)` と `cell[y][x]` の対応を守り、端・斜めの合法手も確認する |
| 問い合わせで盤面が変わる | 判定に `_genmove()` や `_play()` を使う | `_ask()` のみを使う。実行前後の盤面が一致することを確認する |
| 勝者が逆になる、引き分けを誤判定する | 黒白の比較方向を逆にする、空きマスを石数へ含める、同数の分岐を忘れる | 黒勝ち・白勝ち・引き分けの各局面で比較する |
| GUIが応答待ちのままになる | コマンド分岐がない、出力しない、`flush` が不足する | 次のコマンドや `quit` を送らず、1秒以内に応答が届くことをパイプ接続で確認する |
| GUIが誤った結果を表示する | `ask()` を判定に使って途中の応答を出す、二重に出力する、`None` 等を出す | 有効な応答を1行だけ出す。`web.py` は仕様外の文字列も終局・引き分けとして扱い得るので、出力を厳密に確認する |
| 以前の結果が残る | 終局判定結果を保存し、着手後に更新し忘れる | キャッシュを使わず現在の盤面から判定する |

現行の入力処理には、空行の `cmd[0]` 参照、入力終了時の `EOFError`、数値変換失敗の例外処理がない。また、引数付きの `result B` など仕様外入力への応答は定義されていない。これらは入力処理全体の別課題として扱う。対局中を表す応答を、仕様外入力のエラー応答として流用しない。

## 実装後の確認結果

確認用の任意盤面はテストから `Board.cell` に設定した。対戦プログラムに盤面設定用コマンドは追加していない。

| 確認用の盤面 | 期待する結果 |
| --- | --- |
| 初期盤面 | 対局中 |
| 先頭行が `EWBBBBBB`、残り7行が黒だけ | 白はパス、黒は `(0, 0)` に打てるため対局中 |
| 先頭行が `EBWWWWWW`、残り7行が白だけ | 黒はパス、白は `(0, 0)` に打てるため対局中 |
| 先頭行が `EBBBBBBB`、残り7行が黒だけ | 空きが残っていても両色に合法手がなく黒勝ち |
| 全マス黒、全マス白 | それぞれ黒勝ち、白勝ち |
| 満杯で黒32個・白32個 | 引き分け |

上記の局面、問い合わせ後に盤面が変わらないこと、CLIが次コマンドを受け取る前に応答を返すことを `tests/test_result.py` で確認した。`web.py` の `Process` を介して盤面表示・64マスの合法手照会・`result`を連続実行し、応答を受信できることも確認した。

さらに、ランダム対局からパスを含む棋譜を作り、`RequestHandler._make_response()` に通した。片方がパスした時点では `end` が偽、両色が続けて打てず終局した時点では `end` が真となり、石数に合う `score` と盤面が返ることを確認した。実ブラウザ上の描画操作までは確認していない。

実行結果: `python -m unittest discover -s tests -v` は8件成功。`python -m py_compile reversi_player\reversi.py reversi_player\web.py tests\test_result.py` も成功。CLI応答は1秒以内に届く確認を含む。通常時の各応答時間を別途計測するベンチマークは実施していない。

確認範囲では、応答が仕様に合い、問い合わせで盤面が変化せず、パスを終局と誤認せず、GUIサーバー向けの終局・勝敗情報が正しく返ることを確認した。
