# Phase 7.1の長期実験設計

[既存Phase 7](phase7_design.md)の6系列を各10,000局から100,000局へ延長する。学習率0.0000625、ε0.20、γ1、seed 701・702・703、黒視点と半勾配TD(0)を維持する。実行はWindowsの直接CPython 3.13.5。学習履歴と連鎖の起点はPhase 7の証拠を直接参照する。

## 保存と復旧

初期モデル、6起点のstate・モデル、既存開発序盤、固定相手を実ファイルのSHA-256で照合する。Phase 7.1でトレーナーに加える処理は、安全停止と進捗通知、上限100,000局、起点との互換性検査。旧トレーナーの既知SHA-256のみを読み替え、他のソース・初期モデル・乱数の形式・設定・実行環境は同じであることを要求する。3ファイルの改行変換で旧checkpointのhashが変わる問題はGitの属性指定で防ぐ。

1,000局ごとと20,000・50,000・100,000局で、また停止を検知した完局境界で保存する。各試行は一意なディレクトリを作る。トレーナーが棋譜とモデルを保存し、最後に既存形式のstate.jsonを発行する。その内容と親stateのhashを照合して、確定済みの局数を決める。異常終了後は成立している最後の連鎖から続ける。未確定や破損した試行は保存し、分岐が複数成立した場合は再開を拒否する。

管理プロセスはOSの排他ロックを保持する。子プロセスは系列ごとと評価用の別ロックを取り、親のPID・生成時刻を確認する。管理プロセスが失われた場合も、子の処理が完了しロックが解放されてから再開する。停止要求は起動ごとのファイルで伝える。進捗JSONは人の確認用で、確定の判定にはcheckpointを使う。

## 評価と実行

固定節目で全系列の学習を区切り、当該節目の全対局を直列に取得する。Phase 7と同じ12先後交換ペア、評価seed 20261119、既存の固定positional_v1と明示深度2のsearch_v1を使う。同じseedの系列間対局も行う。10,000局分は既存結果の条件とhashを照合して登録する。中断した評価は試行単位でやり直し、完了した同じ評価は再実行しない。smokeの出力先・少数の序盤・局数は本番と分ける。

原証拠を全て残し、正常な試行を上書きしない。出力不足を開始前に見積もり、運転中にも空き容量を検査する。JSON、CSV、Markdownの報告は確定記録から作る。
